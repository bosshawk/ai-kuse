# ワードを追加する前の調査と判断

<!-- ai-kuse-disable -->

`/ai-kuse survey` と `/ai-kuse add` で読む。ワードを一覧に足すかどうか、どう検出するか、重さをどうするかを、用例と件数で決める手順。2026-11 の調査（`research/2026-11-term-survey/README.md`）で使ったやり方をまとめたもの。

## 0. 前提

- 調べるのは「AI の文章に多く、人の技術文書では少ない、または使い方が違う」ワード。AI の文章に多いだけの話題のワード（ベンチ、テナント）や、定着した用語（照合、粒度）は入れない。
- 判断の材料は 3 つの文章群。`survey.py prepare` で作る（初回か、1 か月以上たったとき）。
  - `ai`: 利用者の Claude Code の会話ログの Claude の文章
  - `human`: ChatGPT 公開前（2019〜2021 年）の Qiita の記事
  - `recent`: 今年の Qiita の記事（AI と人が混ざる）
- このスキルの開発の会話（`ai-kuse` を含む文章）は `ai` から外れる。いま調べている会話の id が分かれば `--exclude-session` で外す。
- 利用者が重さや扱いを指定したら、それに従う。数値と食い違うときは、数値を伝えたうえで指定どおりにする。

## 1. 用例を直前の言葉ごとに分ける

1 字や 2 字のワード（層、型、軸、面、形、穴）は、まず使い方を分ける。

```bash
uv run --script ${CLAUDE_SKILL_DIR}/scripts/survey.py neighbors 層
```

ai と human で、上位の複合語と用例を見比べ、次の 3 つに分ける。

| 種類 | 例 | 扱い |
|---|---|---|
| 定着した複合語・用語 | 画面、階層、サービス層、データ型、横軸 | 検出しない（除外する） |
| 人も同じ意味で使う言い方 | 「〜という形で」「この面で」「〜を軸に」 | 検出しない（除外する） |
| AI に特有の使い方 | API 層、ホスト型、比較の軸、攻撃面、前の形に戻す | 検出する |

3 つ目が見つからなければ、そのワードは入れない。

## 2. 検出のパターンを決める

どちらの方式にするかは、人の文章での使い方で決める。

- **除外方式**（例: 層）: 人の使い方がほぼ定着した複合語に限られるとき。`literal` でワード全体に当て、定着した複合語を `exclude` / `exclude_regex` に並べる。新しく作られた複合語（テナント層、MCP 層）にも当たる。
- **限定方式**（例: 型、形、面）: そのワードが分野の中心の用語でもあるとき（型システムの「型」）。AI に特有の形だけを `regex` で書く。

パターンを書くときの注意:
- 前に漢字が続く形（学生の、要素の）に当てたくないときは `(?<![一-龥々])` を付ける。
- 「落とし穴」の「穴」のように、前の字が漢字でない複合語は後読みで外せない。`exclude` に複合語を書く。
- 数字と助数詞の間の空白（4 つの型）を `\s?` で許す。
- 活用は語幹と語尾を分けて書く（崩れ(る|て|た|ま|ない)）。「ませんでした」は「ま」で拾う。

## 3. 数える

```bash
uv run --script ${CLAUDE_SKILL_DIR}/scripts/survey.py count '(?<![一-龥々])素の' '裏で(回|動|待)'
```

10 万字あたりの件数と、ai/human、recent/human の比が出る。根拠の強さは次のように決める。

- **強い**: (1) ai が human の 3 倍以上（10 万字あたり 0.3 以上）で、(2) recent も human の 2 倍以上か、(3) 計測のある出典で増加が報告されている。
- **中**: (1)〜(3) のどれか 1 つ。
- **弱い**: どれも満たさない。

件数の差が小さくても、使い方の違いがはっきりしていれば入れてよい（層: 人の当たりの多くは機械学習の層）。その場合は evidence の note に理由を書く。

## 4. 用例を読む

```bash
uv run --script ${CLAUDE_SKILL_DIR}/scripts/survey.py samples '生(ログ|値|API)'
```

ai の用例を 5〜10 件読み、AI に特有の使い方かを確かめる。次のものは候補から外す。
- 利用者のテンプレートの見出しや欄の名前（公式資料、発行元、症状）
- 1 つの会話だけに集中しているもの（本線、打ち手は ISUCON の会話に集中）。外すかどうかは利用者に聞く
- 人の技術者の口語で、human のほうが多いもの（叩く、畳む、腹落ち、ちゃんと）

## 5. YAML に書く

`terms/tech.yaml` の同じ分類（category）の、warn か info の並びに足す。分類が合わなければ `categories` に足す。

| 項目 | 書き方 |
|---|---|
| `id` | ローマ字の小文字とハイフン |
| `term` | 見出しのワード。意味を限るときは括弧を添える（型（方式・パターン）） |
| `severity` | warn: AI に特有の使い方で、ほぼ常に言い換えたほうがよい。info: 定着した意味でもよく使われ、文脈で決める |
| `match` | 2 章の方式で書く |
| `why` | 何の直訳か、何が書かれないまま済んでいるかを 1〜2 文で |
| `suggest` | 言い換えの候補。差し替えで済まないものは「〇〇の処理」のように中身を書かせる形にする |
| `keep_when` | 1 章で除外した使い方のうち、パターンで外しきれないもの |
| `examples` | ai の実際の用例をもとにした `bad` と、言い換えた `good`。2〜3 件 |
| `evidence` | 書かずに足し、あとで `survey.py evidence --write` で入れる。出典の数値は、自分で開いて確かめたものだけを `note` に書く |

## 6. 確かめる

```bash
uv run --script ${CLAUDE_SKILL_DIR}/scripts/validate.py
```

```bash
uv run --script ${CLAUDE_SKILL_DIR}/scripts/survey.py term <id>
```

`term` は、人の文章で当たった用例を出す。誤検出なら `exclude` を足す。人のふつうの文で当たらないことを、`tests/fixtures/should_not_hit.md` に 1 行足して確かめる（テストは `uv run --with pytest --with pyyaml --with jsonschema pytest -q`）。最後に `survey.py evidence --write` で数値を入れる。

## 7. 記録する

- `research/<年-月>-<題>/README.md` に、調べたワード、数値、用例、入れたものと入れなかったもの、その理由を追記する。事実（数えた数値、確かめた出典）、解釈（判断）、未確認を分けて書く。
- 文章群の偏りを書く。`ai` は 1 人の利用者の Claude だけで、話題が偏っている。`recent` の AI の割合は分からない。
- Web の報告を使ったときは、出典の URL と、自分で開いて確かめたかどうかを書く。
