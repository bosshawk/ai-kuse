# 段落の形の調査（2026-11）

文の終わりで改行するか（段落を分けるか、段落の中で改行するか）の目安を決めるために、AI の文章と人の文章で段落の形を比べました。判断の基準は [references/kaigyo.md](../../references/kaigyo.md) にまとめています。

## 方法

- 文章群は kuchiguse の `survey.py prepare` が作るもの（`~/.cache/ai-kuse`）を使いました。
  - **ai**: Claude Code の会話ログにある Claude の返答と、Claude が Write した `.md`
  - **human**: Qiita の記事（2019〜2021 年、ストック 20 以上）
  - **recent**: Qiita の記事（2026 年、ストック 20 以上）
- 日本語が300字未満の文章は外しました。
- 段落の切り方は tsumekomi.py と同じです（空行で段落を分ける）。見出し・箇条・表・コードは数えていません。
- 段落の中の改行（空行でない改行）も、行ごとに数えました。

```bash
uv run --script scripts/measure.py > results/paragraph_shape.json
```

## 結果

| | ai | human | recent |
|---|---|---|---|
| 文章 | 3,177 | 1,465 | 999 |
| 段落 | 10,899 | 58,118 | 58,128 |
| 1文の段落 | 48.1% | 54.0% | 55.6% |
| 4文以上の段落 | 5.8% | 8.8% | 5.8% |
| 6文以上の段落 | 0.4% | 2.1% | 0.8% |
| 段落の字数（中央値） | 53 | 66 | 56 |
| 段落の字数（上位10%の境） | 120 | 170 | 140 |
| 120字を超える段落 | 9.9% | 21.5% | 14.7% |
| 200字を超える段落 | 1.4% | 6.4% | 3.0% |
| 段落の中の1行が1文 | 50.8% | 80.6% | 70.0% |
| 1文の段落が4つ以上続く文章 | 0.1% | 36.6% | 38.0% |

数値は [results/paragraph_shape.json](results/paragraph_shape.json) にあります。

## 分かったこと

- AI の段落は、人の段落より長くはない。120字を超える段落は、人の半分ほど。
- 違いが大きいのは段落の中の改行。人（Qiita）は段落の中の行の8割が1文で、1文ごとに改行してから空行で段落を分けている。AI は半分ほど。
- 人は1文だけの段落を続けて書くことが多い（4つ以上続く文章が4割弱）。AI はほとんどしない。

## 目安への反映

- `paragraph-sentences`: info を 4 から 3 に、warn を 6 から 5 にした。4文以上の段落（ai の 5.8%）で書き換え方を考え、6文以上（ai の 0.4%）は原則書き換える。
- `paragraph-chars` を足した。info は 120字（ai の上位10%の境）、warn は 200字（ai の 1.4%）。
- 1文の段落の連続は、AI にはほとんど出ないので測らない。判断の基準（kaigyo.md）で「改行しすぎ」として扱う。

## 偏り

- ai は Claude Code の会話の返答が中心で、短い返答が多い。アーティファクト（HTML）はほとんど入っていない。HTML のページでは段落がもっと長い可能性がある。
- human と recent は技術記事。Qiita は段落の中の改行をそのまま表示する。
  - 1文ごとの改行が多いのは、その表示に合わせた書き方とも考えられる。
  - GitHub の `.md` ファイルのように、段落の中の改行を表示しない所では同じ書き方にならない。
- 読みやすさを人に尋ねた調査ではない。多く使われている形を測っただけで、それが読みやすいとは限らない。
