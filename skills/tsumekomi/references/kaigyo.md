# 文の終わりで改行するか

「。」のあとで改行するか、続けて書くかを決めるときの基準です。どの文書にも同じ改行を当てはめる決まりではありません。段落の指摘（`paragraph-sentences`、`paragraph-chars`）を書き換えるときと、書く前に迷ったときに読みます。

根拠は、文化審議会の「公用文作成の考え方」と、このリポジトリの調査（[research/2026-11-paragraph](../research/2026-11-paragraph/README.md)）です。

## 改行の3つの形

文の終わりでできることは3つあります。

1. **続けて書く**: 同じ段落の中で、次の文をそのまま続ける。
2. **段落を分ける**: Markdown では空行、HTML では `<p>` を分ける。読み手は「ここで話が変わる」と受け取る。
3. **段落の中で改行する**: 段落はそのままで、文ごとに行を変える。Markdown では空行を入れない改行、HTML では `<br>`。

3 は、表示する側が改行を見せるときだけ使えます。

| 表示する所 | 段落の中の改行 |
|---|---|
| Qiita、Zenn、GitHub の Issue やコメント、チャット | 見える |
| GitHub の README などの `.md` ファイル、静的サイト | 見えない（前の行とつながる） |
| HTML（アーティファクト） | `<br>` なら見える |

改行が見えない所では、1 と 2 から選びます。文の途中では、どの場合も改行しません（katachi の「手で改行する」）。

## 段落を分けるとき

- 話題や論点が変わる。次の文が「また」「一方」「次に」で始まる、主語が変わる、など。
- 結論や注意の1文を目立たせたい。公用文作成の考え方も、結論はできれば最初の段落で示すとしています。
- 段落が長く、画面で1つの塊に見える。4文以上か、120字を超えたら（tsumekomi の目安）、どこで分けられるかを探す。

## 段落の中で改行するとき

- 段落は分けたくないが、文が3つ以上続いて塊に見える。
- 1文ずつ確かめながら読ませたい（手順の説明、注意書き、チャットの返答）。
- 書く所が、段落の中の改行を見せる所である（上の表）。

人の書いた技術記事（Qiita）では、段落の中の行の8割が1文です。1文ごとに改行し、話題の切れ目で空行を入れる書き方が多く見られます。

## 続けて書くとき

- 次の文が前の文を受けている。「そのため」「つまり」「ただし」「これは」などで始まる文は、前の文と離すと何を受けているかが見えにくい。
- 理由や経緯を順に説明していて、文の間のつながりが中身になっている。
- 1文だけの段落がいくつも続き、どこが話題の切れ目か分からなくなりそう。改行が多すぎると、読み手は改行のたびに「話が変わったのか」と迷います。
- 2文以内で、長さも目安より短い。

## 決め方

1. 段落の文を1つずつ見て、文と文の間ごとに「話題が変わるか」「次の文が前を受けるか」を決める。
2. 話題が変わる所で段落を分ける。
3. それでも長い段落は、つながりが最も弱い所で段落の中で改行する。表示する所が改行を見せないなら、段落を分けるか、文を短くする（一文の目安は tsumekomi の `sentence`）。
4. 前を受ける文の前では分けない。
5. 文書のほかの段落に合わせる必要はない。段落ごとに中身で決める。
