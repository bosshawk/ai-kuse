# tsumekomi

表のセルに説明文が入っている、1つの箇条に事実が3つある、といった詰め込みを見つけます。長さはスクリプトが測り、あなたは書き換えるか残すか、どう書き換えるかを決めます。

目安は「これを超えると読み返しが増えやすい」という線で、見せ方を決めるものではありません。表にするか、箇条書きにするか、文章にするかは文書ごとに選びます。指摘をゼロにすることは目的にしません。

## 使い方の種類

| 呼び出し | すること |
|---|---|
| `/tsumekomi <ファイル…>` | 測って提案する（check）。ファイルは書き換えない |
| `/tsumekomi fix <ファイル…>` | 書き換えると決めた所をファイルに反映する |

対象の決め方は kuchiguse と同じです。引数のファイル → 依頼に貼られた文章（`--stdin --type md`）→ 直前に自分が書いた本文、の順に探し、どれもなければ尋ねます。

## check

1. 測る。
   ```bash
   uv run --script ${CLAUDE_SKILL_DIR}/scripts/tsumekomi.py --format findings <ファイル…>
   ```
   調べるための文書（API の一覧、設定項目の表など）は `--profile reference` を付ける。文書の中に `<!-- tsumekomi: profile=reference -->` と書いてあれば自動でそうなる。
2. 指摘ごとに前後を読み、3つのどれかに決める。
   - **書き換える**: 読み手が読み返しそうな詰め込みになっている。
   - **残す**: `keep_when` に当たる。または、分けると話の流れや手順の順番が分からなくなる。
   - **確かめる**: 分け方に要る情報（どれが要点か、何と何を比べているか）が原文から分からない。
3. 書き換え方を選ぶ。`hint` は例で、使わなくてよい。
   - 段落の指摘（`paragraph-sentences`、`paragraph-chars`）は、先に `${CLAUDE_SKILL_DIR}/references/kaigyo.md` を読む。
     - 文と文の間ごとに、段落を分けるか、段落の中で改行するか、続けて書くかを決める。
     - 1文ごとに機械的に分けない。
   - 文書のほかの所の見せ方に合わせる必要はない。その箇所の中身に合う見せ方を選ぶ。
   - 長さを縮めるために情報を消さない。表の外の注記、本文、別の項目に移す。
   - 原文にない事実、数値、理由を足さない。
4. 次の書式で返す。
   ```
   ## tsumekomi の指摘（N 件: 書き換える X / 残す Y / 確かめる Z）

   | 場所 | 何が | 判断 | 書き換え方 |
   |---|---|---|---|
   | plan.md:42 | 表のセル 48字 | 書き換える | 「理由」の列を足す |
   | plan.md:60 | 一文 92字 | 残す | 規約の引用 |
   ```
   指摘が0件なら「指摘なし」とだけ書く。

## fix

1. check と同じ手順で判断する。
2. 書き換える前に、naoshi があれば数値・URL・名前を控える（`naoshi.py snapshot <ファイル>`）。
3. 「書き換える」と決めた箇所だけを Edit で書き換える。指摘のない所は変えない。
4. もう一度測り、書き換えた所の指摘が消えたことを確かめる。消えていなければもう1回だけ書き換える。
5. naoshi があれば `naoshi.py compare <ファイル>` で、控えた数値・URL・名前が消えていないか確かめる。
6. 変えた所の一覧と、残した指摘とその理由を返す。

## 目安を変える

目安は `${CLAUDE_SKILL_DIR}/limits.yaml` にあります。数値は仮なので、利用者が「この文書は読みやすい」と言った文書を測って調整します。`info` を超えると info、`warn` を超えると warn として出ます。

測らない範囲は `<!-- tsumekomi-disable -->` と `<!-- tsumekomi-enable -->` で囲みます。Markdown では行末の `<!-- tsumekomi-ignore -->` でその行を外せます。
