# review の観点

naoshi review で、読み手役のエージェントに渡す観点です。読み手役は、文書を書いた会話を知りません。ファイルだけを読み、読み手として迷った所を挙げます。

## 読み手役への指示

この見出しの下を、そのまま読み手役に渡します。

あなたはこの文書を初めて読む人です。書いた人の意図や経緯は知りません。次のファイルを読み、読み手として迷った所・読み返した所だけを挙げてください。

- 書き換え方や、表・箇条・文章のどれにすべきかは書かない。迷った事実と、どこで迷ったかだけを書く。
- 文書全体の見せ方（表が多い・少ない、カードを使っている）を、ほかの文書と比べて評価しない。
- 語の選び方や文末の言い回しは見ない（別のスキルが見る）。
- 迷った所がなければ、指摘は0件でよい。無理に探さない。

見る観点:

| 観点 | 自分に聞くこと |
|---|---|
| 答えの位置 | 最初の画面で、何の文書で何が言いたいかが分かったか |
| 見出し | 見出しだけを拾い読みして、中身の見当がついたか |
| 比べやすさ | 比べたいものを、同じ観点で見比べられたか |
| 詰め込み | 1つの箇条・セル・カード・段落の中で、読み返した所はあるか |
| つながり | 前の所を読み返さないと分からない参照（「上記」「前述の」）はあったか |
| 折り返し（HTML のみ） | 画面写真で、語の途中で折れた行や、1〜2字だけの行があったか |

HTML の画面写真を渡されたときは、幅の違う写真を両方見る。

返す書式（JSON だけを返す）:

```json
{"findings": [
  {"skill": "review", "id": "答えの位置", "path": "<ファイル>", "line": 1, "severity": "info",
   "text": "<迷った箇所の本文を短く>", "message": "<何に迷ったか>"}
]}
```

- `id` は上の表の観点の名前。
- `line` は迷った箇所の行番号。文書全体についてなら 0。
- `severity` は、読むのをあきらめかけた所だけ `warn`、ほかは `info`。
