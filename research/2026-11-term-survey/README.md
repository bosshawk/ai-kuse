# 語の調査（2026-11）

`terms/tech.yaml` に入れる語を、Web の報告と手元の文章の集計で調べた。調べたのは 2026-11-23。

## まとめ

- 語は 41 から 94 に増やした。Web の報告と手元の集計を見て、53 語を足した。
- 94 語の根拠の強さ（判定の決め方は「根拠の強さ」の項）
  - 強い: 48 語。手元の集計で AI の文章に 3 倍以上多く出て、さらに 2026 年の Qiita でも増えているか、出典 A で増加が報告されている
  - 中: 30 語
  - 弱い: 16 語。どの集計でも、AI の文章に多いとは言えなかった。登録したままにしてある
- いちばん目立った語は「正本」と「台帳」。2021 年の人の記事には 0 回で、Claude の文章では 10 万字あたり 8 回を超えた。
- 人のエンジニアの口語（叩く、畳む、吐く、地雷、腹落ち、ちゃんと）は、手元の AI の文章にはほとんど出なかった。AI の口癖とは別のものとして登録していない。

## 事実・解釈・未確認

- **事実**: 下の表の数値は、下記の 3 つの文章群に `scripts/check.py` と同じ検出処理を当てて数えたもの。出典 A の数値は、記事を開いて確かめた。
- **解釈**: 「強い・中・弱い」の判定、各語の重さ（warn / info）、言い換えの候補は、私の判断。
- **未確認**: 出典 B（約 81 万件の調査）の数値は、サブエージェントの報告を見ただけで、記事を自分では開いていない。そのため YAML の evidence には書いていない。

## 方法

### 比べた 3 つの文章群

| 名前 | 中身 | 日本語の文字数 | 件数 |
|---|---|---:|---:|
| AI | Claude Code の会話ログ（`~/.claude/projects`）にある Claude の返答と、Claude が Write した .md。2026-07-20〜11-23、332 セッション。この調査をした会話は除いた | 142 万字 | 4,038 ブロック |
| 人2021 | Qiita API の記事。作成日 2019-01-01〜2021-12-31、ストック 20 以上で検索した新しい順 1,500 件。実際に取れたのは 2021-08-21〜12-31 の分 | 434 万字 | 1,500 本 |
| Qiita2026 | Qiita API の記事。作成日 2026-01-01 以降、ストック 20 以上の新しい順 1,000 件（2026-02-19〜11-19）。AI と人の文章が混ざっている | 401 万字 | 1,000 本 |

どの文章群も、コードブロック、インラインコード、URL を取り除いてから数えた。

### 数え方

1. **登録した語**: `check.py` の検出処理（除外語を含む）を当て、10 万字あたりの件数を出した（`scripts/remeasure.py`）。
2. **新しい候補（名詞）**: 漢字 2〜4 字の連なりと、3 字以上のカタカナ語を数えた（`scripts/discover2.py`）。残したのは次の両方を満たす語。
   - AI の文章で、人2021 の 3 倍以上（log2 で 1.6 以上）
   - Qiita2026 で、人2021 の 2.5 倍以上（log2 で 1.3 以上）

   2つ目の条件は、私の作業の話題の語（ISUCON のベンチ、テナントなど）を外すために入れた。残った約 300 語から、話題の語と定着した用語を目で外した。
3. **新しい候補（動詞・言い回し）**: 正規表現で候補を書いて数えた（`scripts/measure.py`。Web の報告の語は `results/patterns_web.json`）。
4. 候補ごとに、AI の文章から用例を数件ずつ抜き出し、AI 特有の使い方かを読んで確かめた。

### 根拠の強さ

- **強い**: 次の (1) を満たし、さらに (2) か (3) を満たす。
  - (1) AI の文章で、人2021 の 3 倍以上（10 万字あたり 0.3 以上）
  - (2) Qiita2026 で、人2021 の 2 倍以上
  - (3) 出典 A に増加の数値がある
- **中**: (1)〜(3) のどれか1つだけを満たす。
- **弱い**: どれも満たさない。

## 調べたが入れなかった語

| 理由 | 語 |
|---|---|
| 人の文章のほうが多い、または差がない（人のエンジニアの口語） | 叩く、畳む、吐く、地雷、腹落ち、肌感、手触り、ちゃんと・きちんと、きれいに、丁寧に、愚直に、地味に、落とし込む、押さえる、手戻り、踏む、刺さる、担う、抱える、投げる |
| 定着した用語で、言い換えると不正確になる | 照合（認可の用語）、往復（round trip の定訳）、経路、切り分け（障害対応の用語）、症状、整合、粒度 |
| 手元のテンプレートの見出しや欄の名前 | 公式資料、発行元（「示唆」は見出しの形を除いて登録した） |
| AI の文章に少なく、増加が Qiita2026 だけ | 核心、単なる、強み、正面から、踏み込む、浮き彫り、伴走、宙に浮く、正典 |

## 弱い 16 語について

ゲート、解像度、吸収する、筋がいい、責務、肝、生やす、一級市民、衛生、本稿、握る、噛ませる、門、表面積、背骨、屋台骨 は、今回の 3 つの文章群では AI の文章に多いと言えなかった。ただし、AI の文章は 1 人の Claude の利用に限られる。そのため、ほかのモデルや使い方で多い可能性は残る。消すかどうかは利用者の判断に任せ、登録したままにしてある。

## その後の変更（2026-11-23）

弱い 16 語について、利用者が次のように決めた。結果の表の数値は調査した時点のまま。

- info にした: ゲート、解像度、責務、衛生
- 削除した: 屋台骨、一級市民
- warn にした: 吸収する、筋がいい、肝、生やす、本稿、握る、噛ませる、門、表面積、背骨

あわせて、`terms/tech.yaml` の語を分類ごとに並べ替えた（分類の中は warn を先にした）。語は 92 になった。

## 偏り（サンプルの限界）

- AI の文章は、1 人の利用者の Claude（Opus 系）だけ。話題は ISUCON、OAuth・MCP、電子帳簿保存法などに偏っている。利用者の CLAUDE.md や yomiyasu の決まりで文体が調整されている会話も含む。そのため、GPT や Gemini の癖は測れていない。
- 人2021 は、Qiita のストック 20 以上の記事（よく読まれた記事）で、2021 年後半の 5 か月分だけ。
- Qiita2026 は、AI と人の文章が混ざっている。AI の割合は分からない。
- 1 つの会話で同じ語が何度も出ると、件数が大きく出る（本線、打ち手は ISUCON の会話に集中している）。
- 統計的な検定はしていない。

## 再現の手順

```bash
scripts/fetch_qiita.sh
```

取得した記事と、ログから取り出した文章は `data/` に置き、リポジトリには入れない（Qiita の記事の本文と、会話ログを含むため）。そのあと `analyze.py`、`discover2.py`、`measure.py`、`remeasure.py` を `data/` の中で `uv run --script` で実行する。`results/` には件数だけを置く。
